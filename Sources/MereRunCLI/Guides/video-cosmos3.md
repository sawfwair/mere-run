# Cosmos3-Edge

## Purpose

Run NVIDIA Cosmos3-Edge locally through the native Swift/MLX implementation.
One pinned checkpoint provides image and video generation, image editing,
image/video conditioning, action prediction, forward and inverse dynamics,
camera-controlled world transitions, and the multimodal reasoner.

The runtime does not launch Python, PyTorch, Diffusers, or a remote service.

## Required Model

```bash
mere.run model pull video-cosmos3-edge-mlx
```

The managed model pins `nvidia/Cosmos3-Edge` at revision
`6f58f6b4c91288838e60b6bcb2cc45d997e961de`. The model is governed by
OpenMDW-1.1. The public pull retains `LICENSE.md` and does not add a separate
mere.run acceptance gate.

## Generation Modes

```bash
# Text to image
mere.run video cosmos3 "a moss-covered observatory at dawn" \
  --mode text-to-image --width 512 --height 512 -o observatory.png

# Image edit
mere.run video cosmos3 "turn on the warm ceiling lights" \
  --mode image-to-image --image room.png -o room-lit.png

# Image to video
mere.run video cosmos3 "the camera slowly approaches the doorway" \
  --mode image-to-video --image doorway.png \
  --width 512 --height 320 --num-frames 17 -o approach.mp4

# Video to video
mere.run video cosmos3 "convert the scene to a moonlit winter night" \
  --mode video-to-video --video input.mp4 \
  --width 512 --height 320 --num-frames 17 -o winter.mp4
```

Published mode defaults are applied when `--steps`, `--guidance-scale`, or
`--shift` are omitted:

- text-to-image: 50 steps, CFG 4, shift 3
- text/image/video generation and image editing: 35 steps, CFG 6; shift 5 for
  image operations and 10 for video
- action modes: 30 steps, CFG 1, shift 3

Video frame counts must be `4n+1`. Width and height must be divisible by 16.
`--schedule nvidia` is the checkpoint-native shifted-flow UniPC schedule;
`--schedule published-karras` exposes the published Karras-flow alternative.

## Actions And Navigation

Forward dynamics consumes an image plus normalized model-space action rows.
Each row must match the selected domain's published width; the runtime pads it
to the checkpoint's 64-dimensional action representation without changing the
model-space values.

```bash
mere.run video cosmos3 "continue through the same corridor" \
  --mode forward-dynamics \
  --image vesper.png \
  --action-domain camera_pose \
  --action-file camera-actions.json \
  --action-chunk-size 60 \
  --action-resolution 256 \
  -o vesper-forward.mp4
```

For `camera_pose`, use normalized 9D translation-plus-column-rot6d values; do
not pass meters as action tensor values. The built-in world server ships the
exact 60x9 NVIDIA reference trajectory, maps semantic camera commands onto
that calibrated model-space path, and keeps the model and terminal latent
warm:

```bash
mere.run world serve \
  --backend cosmos3 \
  --model video-cosmos3-edge-mlx \
  --state-directory ./vesper-world \
  --prepare
```

## Policy And Inverse Dynamics

Use `--mode policy` with an image or video to predict a 64-dimensional action
sequence. Use `--mode inverse-dynamics` with a video to infer the action
sequence that connects its frames. Predicted actions are written beside the
media output or to `--actions-output`.

```bash
mere.run video cosmos3 "navigate toward the open doorway" \
  --mode policy --image vesper.png \
  --action-domain camera_pose \
  --actions-output policy.json

mere.run video cosmos3 "infer the camera motion" \
  --mode inverse-dynamics --video movement.mp4 \
  --action-domain camera_pose \
  --actions-output inferred-actions.json
```

## Multimodal Reasoner

The reasoner shares the checkpoint's understanding transformer with the native
packed SigLIP2 vision tower and projector:

```bash
mere.run video cosmos3 \
  "Describe the navigable paths and likely obstacles." \
  --mode reasoner \
  --image vesper.png \
  --max-new-tokens 128
```

Pass `--video` instead of `--image` for video reasoning and use
`--max-video-frames` to bound sampled frames. `--temperature 0` selects greedy
decoding.

## Exactness And Limits

- Transformer, vision tower, projector, VAE, tokenizer, mRoPE, action packing,
  and UniPC logic are implemented in Swift/MLX.
- Numerical fixtures are generated by NVIDIA's pinned Cosmos framework commit
  `ed8287fd7477113f8ac4f6b84290514d55cf0cdc`.
- The world server is single-session and admits one transition at a time.
- The first world transition needs `sourceImage`; subsequent requests may
  chain from the retained terminal state.
