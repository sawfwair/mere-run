# D1 decisions

LiquidAI's [D1 release](https://www.liquid.ai/blog/d1-open) provides two
decision models that score typed answers without generating tokens. Both run
locally in Swift/MLX through `text decide` on macOS and Linux. Use D1-3B for
text, JSON, and image decisions, or the smaller D1 omni 600M when a decision
also depends on audio. iOS includes catalog metadata only, not D1 inference.

## Choose a checkpoint

The memory column lists the catalog's minimum and recommended unified memory.

| Model ID | Precision | Inputs | Download | Memory (minimum / recommended) |
| --- | --- | --- | --- | --- |
| `text-decide-d1-3b-bf16` | BF16 | Text, JSON, images | About 6.3 GB | 12 GB / 16 GB |
| `text-decide-d1-omni-600m-fp32` | FP32 | Text, JSON, images or audio | About 2.4 GB | 8 GB / 16 GB |

## Install

Original LiquidAI safetensors load directly. Tensor names and layouts are
adapted in memory, so you don't need a checkpoint conversion or Python setup.

D1 uses the custom LFM Open License v1.0. Review its terms, then pull either
model:

```bash
mere.run model pull text-decide-d1-3b-bf16 --accept-model-license
mere.run model pull text-decide-d1-omni-600m-fp32 --accept-model-license
```

Inference doesn't download weights; install the model first or pass an explicit
local checkpoint directory to `--model`. D1 is available through the CLI only.

## Decide

Save this request as `request.json`:

```json
{
  "state": "The parcel arrived on time, but the glass inside was broken.",
  "questions": {
    "arrived": {"type": "noul", "instructions": "Did the parcel arrive?"},
    "route": {
      "type": "choice",
      "instructions": "Which team should handle the claim?",
      "criteria": {"shipping": "Late delivery", "damage": "Damaged goods"}
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgent is this claim?",
      "criteria": ["low", "medium", "high"]
    }
  }
}
```

Check the token budget, then evaluate the request:

```bash
mere.run text decide --model text-decide-d1-3b-bf16 --input request.json --preflight
mere.run text decide --model text-decide-d1-3b-bf16 --input request.json --pretty
```

The CLI writes JSON to stdout and can also save it with `--output`. Text
inference uses the shared 16 GiB available-memory admission floor; `--preflight`
doesn't reserve inference memory.

## Request format

`state` accepts any JSON value, including null. Questions are a named object.

- `choice`: options keep their source order, and ties choose the first option.
- `score`: requires 2–10 ordered levels and returns the expected level.
- `noul`: returns `P(yes)`.

`usage.output_tokens` is always zero. Each question uses an independent forward
pass, and `usage.input_tokens` counts the rows actually executed. The upstream
tree-packing optimization isn't implemented.

## Images and audio

Add `"images": ["/path/to/image.png"]` for either model, or
`"audio": "/path/to/clip.wav"` for omni. A request accepts up to 16 images or one
audio file. Requests that mix images and audio, or that include videos, URLs, or
processor overrides, are rejected.

- **Audio** is decoded to 16 kHz mono, capped at 30 seconds, and padded to at
  least 0.5 seconds. Omni's media prefix attends only to media; text attends to
  both.
- **Images** use smart resize, up to ten 512-pixel tiles plus a thumbnail,
  packed 16-pixel RGB patches, SigLIP2 NaFlex, and a 2×2 pixel-unshuffle
  projector. D1-3B first caps each source image at one megapixel with
  Pillow-compatible bicubic resampling, then uses the released bicubic tensor
  resize. Omni uses bilinear tensor resize. Both preserve torchvision's
  intermediate 8-bit rounding. Preflight rejects extreme aspect ratios that
  exceed the 1,024-patch crop budget.

## Token budgets

`--preflight` decodes media and reports per-question token counts, truncated
state tokens, option order, and omni marker positions without loading weights.
The request field `max_tokens` can lower the checkpoint context limit.

- D1-3B rejects prompts that exceed its 32K context.
- Omni reserves space for its complete option markers and truncates state on the
  right. It applies the released text budget: 16K for text, 896 text positions
  with images, or 15,360 with audio, further reduced by the media prefix length.
  Caller text can't forge omni's reserved delimiters.

## Implementation

`MereRunD1Model` owns model computation, and `MereRunCore/D1` owns orchestration.
The original checkpoints load directly, with strict key and shape checks for the
trunk, head, vision, and FP32 audio weights. D1-3B max-pools each answer's
single-token forms and normalizes over options. Omni uses a bidirectional LFM
encoder and a two-layer option head. It reverses its internal false/true order
for noul responses and applies the released temperature calibration only to
text-only requests.

## Validation

Released-checkpoint CLI execution and independent probability comparisons passed
on 2026-10-09: text and images for BF16 D1-3B, and text, images, and audio for
FP32 omni. Both original safetensors matched their published SHA-256 hashes.
Across 15 decisions, the maximum absolute probability differences from the
original CPU reference were 0.00128 for D1-3B and 0.0000089 for omni. Chosen
options and executed token counts agreed. The
[D1 qualification record](../benchmarks/d1-native-qualification-2026-10-09.md)
lists the inputs, reproduction steps, and limits.

Independent, small FP32 fixtures in `Tests/MereRunCoreTests/Fixtures/D1` come
from those revisions' original PyTorch code. They cover both trunks, isolation
of media prefixes, the option head, vision projection, normalized log-mel
features, FastConformer audio, and exact antialiased image pixels. Optional
tests compare both original tokenizers and load complete checkpoints with text,
image, and audio requests. To reproduce the arithmetic and prompt fixtures, run
`scripts/fixtures/export-d1-reference.py`. To run the tests, use
`swift test --filter D1` and `./scripts/check.sh`.

The committed released-checkpoint regression needs only the original model
assets and native Swift/MLX execution:

```bash
MERERUN_TEST_MLX_DEVICE=gpu \
MERERUN_TEST_D1_RELEASED_CHECKPOINTS=/path/to/original-checkpoints \
  swift test --filter D1ReleasedCheckpointTests
```

That directory contains `causal/` and `omni/` checkpoint folders. Python is
needed only to regenerate the independent reference answers with
`scripts/fixtures/export-d1-release-reference.py`.

These cases don't establish benchmark accuracy, all-input numerical
equivalence, or edge latency, and the record makes no speed claim. Omni
misanswers two speech questions in both implementations.
